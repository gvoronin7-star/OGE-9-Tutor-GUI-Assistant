# Руководство по внесению вклада

Спасибо за интерес к проекту **OGE Tutor GUI**! 🎉

## Как внести вклад

### 1. Сообщить об ошибке

Если вы нашли баг, создайте [issue](https://github.com/your-username/oge-tutor/issues) с меткой `bug`:

- Опишите проблему подробно
- Укажите версию проекта
- Приложите скриншоты (если применимо)
- Добавьте шаги для воспроизведения

### 2. Предложить улучшение

Для новых функций создайте [issue](https://github.com/your-username/oge-tutor/issues) с меткой `enhancement`:

- Опишите предлагаемую функцию
- Объясните, какую проблему она решает
- Добавьте примеры использования

### 3. Создать Pull Request

1. **Fork** репозиторий
2. Создайте ветку для изменений:
   ```bash
   git checkout -b feature/amazing-feature
   ```
3. Внесите изменения и сделайте commit:
   ```bash
   git commit -m 'Add: amazing feature'
   ```
4. Push в ветку:
   ```bash
   git push origin feature/amazing-feature
   ```
5. Откройте [Pull Request](https://github.com/your-username/oge-tutor/pulls)

## Стиль кода

### Python

- Следуйте [PEP 8](https://pep8.org/)
- Используйте `snake_case` для переменных и функций
- Используйте `PascalCase` для классов
- Комментарии на русском языке
- Docstrings в формате Google

### Форматирование

```bash
# Автоматическое форматирование
black .
isort .
```

## Типы коммитов

Используйте префиксы для ясности:

| Префикс | Описание | Пример |
|---------|----------|--------|
| `feat:` | Новая функция | `feat: добавить тёмную тему` |
| `fix:` | Исправление бага | `fix: исправить краш при загрузке` |
| `docs:` | Изменения в документации | `docs: обновить README` |
| `style:` | Форматирование | `style: исправить отступы` |
| `refactor:` | Рефакторинг | `refactor: оптимизировать поиск` |
| `test:` | Тесты | `test: добавить тесты для RAG` |
| `chore:` | Вспомогательные изменения | `chore: обновить зависимости` |

## Правила для Pull Request

1. **Название PR**: Используйте тот же формат, что и для коммитов
2. **Описание**: Подробно опишите изменения
3. **Связь с issue**: Укажите номер issue (если есть)
   ```
   Closes #123
   ```
4. **Тесты**: Добавьте тесты для новых функций
5. **Документация**: Обновите документацию при необходимости

## Процесс ревью

1. Один из мейнтеров проверит ваш PR
2. Возможны комментарии и предложения
3. После одобрения PR будет merged
